# Derive reception collection independently from player tracking

VaporStats derives each scheduled reception candidate set from catalog eligibility, persisted activity signals, freshness, and prior evidence rather than treating player tracking rows or durable jobs as the queue. Every admitted eligible entity receives a cheap Steam review-summary assessment; compatible populations with at least 50 lifetime reviews may produce Current Player Scores, while smaller populations remain successful but insufficient evidence until a later catalog activity signal. Multiple signals collapse into one candidate, ordinary failures remain naturally eligible behind clean peers, and a successful collection clears the entity’s minimal failure streak.

SQLite remains authoritative for reception evidence, checkpoints, and the four-field failure streak required for fair ordering. Server-only Markdown snapshots expose the current queue and active failures, while a bounded JSONL tail records the latest 50 cron summaries. This rejects a generic job framework, traffic-driven scheduling, and title-specific retry policy: the existing cron performs bounded work, rate limits stop the pass, and later crons reconsider eligible failures.

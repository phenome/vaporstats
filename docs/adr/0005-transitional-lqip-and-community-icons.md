# One sticky game header with FLIP morphing and dual LQIP storage

**Status:** Accepted

VaporStats uses a stable wrapper as one sticky header element (`position: sticky; top: 3.5rem`, below the 56px site header) that retains the expanded header height. The inner header is neither fixed nor sticky: it retains the expanded layout boxes while its single DOM subtree morphs in place. The expanded and compact states never render separate header subtrees. Each persistent identity element has exactly one DOM instance inside that inner header: the title, Steam store link, status tag, main released date, and artwork shell.

The header uses scroll-position-driven FLIP-style interpolation driven by a single linear 0–100% timeline. VaporStats uses native CSS Scroll-Driven Animations (`animation-timeline: scroll(root block)`) as the primary driver, with direct-DOM `requestAnimationFrame` updates as the fallback when scroll-driven animations are unsupported or when `prefers-reduced-motion: reduce` is active. Scrolling never triggers React component renders or state updates.

When the expanded hero reaches the sticky boundary, `useHeroGeometry` captures the expanded and compact geometry for each element. The driver then interpolates translation, scale, and dimensions continuously over 0–100% progress without the prior 0–60% exit and 40–100% destination split:

- **Continuous 0–100% timeline:** Fades, FLIP transforms, reciprocal typography scaling, and artwork crossfade progress together across the shared range. Elements without compact destinations (description, lifecycle overview, developer/publisher cards, and narrow-screen hidden identities) move upward with the root while fading out, counter-scaled with reciprocal `scaleY` so glyph proportions remain natural. Interactive elements become inert at 100% progress.
- **Persistent identity morph:** Persistent elements (title, artwork shell, status, date, store link on desktop) translate and scale between their expanded and compact geometries. Title scaling uses uniform transform scaling derived from compact/expanded height rather than progress-dependent font-size/line-height clamp, avoiding typography relayout during scroll.
- **Landscape-to-square icon mapping:** The artwork shell remains the same element while transforming from landscape hero dimensions to compact 32×32. The crossfading layers use constant mappings: the header artwork uses `object-fit: cover` to fill the landscape shell, while the square Community icon uses `object-fit: fill` across the entire morph. The square icon horizontally fills the landscape source shell at progress 0 (hidden by opacity 0); as the shell transforms toward 32×32, that fill mapping naturally restores the icon to square while opacity rises to 1. Centered aspect-preserving mapping or `cover`→`fill` switching is rejected because it crops or distorts intermediate pixels. When both images resolve to the same asset, one opaque header layer renders without crossfade.

**No-reflow invariant:** FLIP morphing must not move downstream document content. The stable wrapper remains `position: sticky` at `top: 3.5rem` and permanently reserves the measured expanded header height as equal flow compensation. The inner header is neither fixed nor sticky; it retains the expanded layout boxes and morphs only with transforms and opacity. The wrapper's transparent region does not intercept pointer events; interactive survivors opt into pointer events. Elements without destinations fade only and never participate in geometry interpolation.

To prevent layout shifts and blank image flashes across both states:

1. **Dual LQIP storage:** SQLite stores precomputed inline base64 placeholders for both the full landscape header image (`apps.header_lqip`) and the compact square icon (`apps.icon_lqip`). Placeholders are generated with Bun 1.4 native image processing (`Bun.Image`).
2. **Transitional square LQIP:** Until ingestion backfills the Steam Community icon hash (`apps.icon_hash`), derive the square placeholder by resizing the stored header image to 32×32 without cropping, preserving the full image content in the reduced bitmap. When the missing icon is rendered, the generated placeholder may be lazily backfilled into the database.
3. **Asset upgrade:** Once `icon_hash` is ingested, the artwork shell uses Steam's official 1:1 Community icon for the compact visual state.

# Identify creators independently of publisher URL slugs

Steam's public `appdetails` provides developer and publisher **names**, not stable creator IDs. Steamworks lets a partner associate multiple displayed names with one [Creator Homepage](https://partner.steamgames.com/doc/store/creator_homepage). The [Street Fighter 6](https://store.steampowered.com/app/1364780/), [Mega Man Legacy Collection 2](https://store.steampowered.com/app/495050/), and [Mega Man 11](https://store.steampowered.com/app/742300/) store pages link three CAPCOM spellings to `/publisher/capcom`; that homepage exposes the numeric [group news hub 33273264](https://store.steampowered.com/news/group/33273264). This verifies one alias group, not a universal mapping from Store names, vanity URLs, or AppIDs to creator IDs. In contrast, [Weebles vs Grebals](https://store.steampowered.com/app/3570510/) links `GD Studio` to `/curator/45043985`, while [Whisper of the House](https://store.steampowered.com/app/2589500/) presents `元气弹工作室(GD Studio)` as a name-filtered search link. A shared Latin substring does not verify common ownership. A local catalog sample also exposed unrelated non-Latin names collapsing into the old ASCII fallback slug `publisher`; the sample is not proof of complete production coverage. The separate research report and bounded sampling evidence remain on the research branch.

**Decision:** Persist creators under internal numeric IDs, exact-name aliases, and per-app developer/publisher associations (including every supplied name). Merge only names supported by a verified shared Steam Creator Homepage group identity; initially only the three observed CAPCOM variants share group 33273264. A curator link, homepage vanity path without a verifiable group, similar spelling, case-insensitive match, transliteration, or missing link does not establish identity. Unresolved names stay separate, including the GD pair and every non-Latin name formerly sharing `publisher`. Empty names create no association. Catalog updates replace an app's associations, preserving other apps' links and established aliases; orphaned identity rows alone do not make a creator visible. Local scalar developer/publisher columns can remain for existing game display, but must not define directory membership.

Directory and detail queries operate on associated eligible, playable root apps only, count each app once per creator even when it has both roles, and expose both role flags. Rank by unique game count descending, then display name and ID for deterministic ties; obtain the total independently and page in SQL with `LIMIT/OFFSET`, not by loading every identity into JavaScript. Public canonical URLs use `/publisher/{internal-id}-{Unicode-safe-slug}`; the ID resolves identity and a stale or incorrect suffix redirects to the current canonical path. Name-only links use the reserved `/publisher/~{encoded-exact-name}` form (old ASCII slugs cannot contain `~`), resolve the exact alias, then redirect. A bare old ASCII slug redirects only when all matching aliases, including an exact alias spelled like that slug, belong to one identity. Ambiguous historical slugs such as `publisher` return 404 rather than choosing an identity. Unambiguous old mixed-case or encoded Unicode name links remain supported. No automatic external-ID enrichment is implied by this URL scheme.

The migration backfills names and role associations from existing scalar app fields, then future ingestion stores full developer/publisher arrays; names absent from the historical scalar fields cannot be recovered retroactively from those fields. Both directory and detail routes and their name-only callers must use the identity resolver before treating ID URLs as canonical. A future newly verified homepage group can be attached only after checking existing alias ownership and safely reconciling associations; uncertain or renamed homepage evidence does not trigger automatic merges. `LIMIT/OFFSET` gives bounded reads but, without a snapshot across requests, concurrent catalog changes may move entries between pages.
